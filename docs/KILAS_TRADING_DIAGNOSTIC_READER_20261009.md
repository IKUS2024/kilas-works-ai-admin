# Recorded DEMO diagnostic reader

The Trading pilot dashboard has a distinct local diagnostic report reader. It accepts bounded UTF-8 JSON for `kilas-collector-diagnostic-v1` / `READ_ONLY_DEMO_DIAGNOSTIC_CAPTURED`, with DEMO observations, disabled runtime/broker/AI/paper flags, unimplemented producer acceptance and completed SDK shutdown. This is a historical, user-supplied report; validation does not prove authenticity, broker account classification, current connectivity or trading readiness.

Full reports stay in browser memory during parsing. There is no diagnostic upload endpoint, form submission, persistence, telemetry or integration. A fresh allowlisted projection contains only capture timestamp, fixed diagnostic outcome, synthetic flag, observation/request/reply counts, fixed clock outcomes/uncertainty and hypothetical direction/lot/notional/cap statuses. Account identifiers, balance, credentials, server/session identifiers, history, raw NTP packets, hashes and arbitrary fields are discarded. Rendering uses `textContent`. Selection is cleared after reading; clear/reload/page exit drops the displayed summary. The source file on the user's device is unaffected.

Limits: 128 KiB before reading and after UTF-8 decoding, 32 nesting levels, 20,000 parsed values, at most four matching collection/clock/market observations, sixteen NTP requests and four risk records with at most two distinct BUY/SELL scenarios each. Duplicate keys, prototype keys, nonfinite values, incompatible flags/statuses, invalid UTC dates, inconsistent counts and inconsistent cap outcomes are rejected. The report cap must remain USD2000. A hypothetical scenario within that cap still grants no execution permission.

The report explicitly remains historical. Clock assurance is unauthenticated; broker offset/DST profile, GOLD mapping and freshness remain unverified. Costs are unknown, history incomplete, net P&L/drawdown unevaluated. No local clock comparison grants freshness. BLOCKED is retained for hypothetical notional above the cap.

The existing 8 KiB market-only observation upload, tenant/auth/CSRF protections, `analysis.market_source = None`, MOCK paper controls, risk limits, SL/strategy and other products are unchanged. No private report is committed or sent to production. Actual Library report text was inspected and passed through the offline parser in memory; byte-level SHA256 verification was unavailable because supported materialization failed. Synthetic fixtures cover the reusable tests.

Validation before release: seven parser/security test methods (with rejection subcases), 38 Trading, 17 analysis, 15 observation, four host-isolation and 16 Finance tests pass. Browser QA passes at 1440/768/390/320 pixels, including local import without network requests or stored-state mutation, disabled broker/AI controls, rejection, clear/reload, and all existing MOCK workflows. JavaScript syntax and diff whitespace checks pass. CI additionally runs native PostgreSQL and applicable shared UI regressions. Production authenticated pilot QA requires an existing authorized session; public smoke cannot replace that acceptance check.
