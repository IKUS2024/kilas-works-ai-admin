## Implemented surface and flow

The customer-owner-only `/kilas-learning` page extends the existing `kilas-light` customer shell and task selector. It uses a Learning-scoped CSS file, the shared feature navigation, existing Manrope/white-surface/orange-control visual language, and a compact setup form. The form selects target language (English, Mandarin, Spanish), explanation language (Indonesian, English, Mandarin, Spanish), starting level, and existing Kilas Male/Female voice. It requires audio-processing consent before Start. When readiness is false, Start is disabled and the page explains the funding/activation hold. During a call the page exposes listening/speaking status, microphone mute, resume, and End; it does not display a transcript or pronunciation score.

Start creates one owner-fenced session and queues the tutor's first greeting. The browser AudioWorklet downsamples microphone input to mono PCM16 at 16 kHz. HTTP chunks flow while the learner speaks to the Kilas server; only the server holds the ElevenLabs key and opens an outbound WebSocket to `scribe_v2_realtime`. After 3 seconds of detected silence the browser commits the utterance. The tutor receives only committed text. There is no batch STT fallback or automatic paid retry. The server uses the existing AI Chat OpenAI Luna project configuration for the lesson response. Stable phrases are sent once to the existing Kilas Male/Female ElevenLabs Multilingual v2 TTS path; each private clip is published and played in order while later response phrases can still be generated. The microphone is paused while the tutor speaks, so barge-in is not supported.

The session is capped at 30 minutes or 40 turns. An utterance has a browser limit around 23–24 seconds, a 25-second PCM ceiling, and a server connection ceiling of 45 seconds. No speech for 15 seconds leaves the browser listening attempt without opening a paid WebSocket; the backend waits at most 8 seconds for first PCM and stops an idle stream after 8 seconds. End fences further work, stops local microphone/playback, and clears private session text and clip bytes. Dispatched provider work can still incur cost. Existing AI usage and Audio balances/jobs remain the accounting paths for tutor text and generated speech; Learning adds its own bounded realtime STT allowance and a 6,000-character rolling 24-hour TTS dispatch cap.

## Activation hold and cost boundary

**Realtime Learning stays OFF.** `KILAS_LEARNING_REALTIME_ENABLED` defaults to `false`; the status of `KILAS_LEARNING_ENABLED` alone does not admit a session. `learning.ready()` also requires the existing explicit owner allowlist and valid STT policy, provider credential presence, existing verified Luna model/STT/reference/project gates, and a finite `KILAS_LEARNING_REALTIME_BUDGET_MICRO_USD` between **4,875** and the existing STT account budget (inclusive). The owner-scoped Learning cap and the existing global STT cap are checked before each STT admission. A separate limit allows at most 20 Learning STT admissions per owner per rolling hour. Each admitted connection reserves **4,875 micro-USD**, calculated conservatively from the 45-second maximum at $0.39/hour. A dispatched connection with uncertain actual charge retains its reservation; an undispatched one is released. The reserve is an internal ceiling, **not a supplier invoice or evidence of actual metering**.

ElevenLabs lists [Scribe v2 Realtime at $0.39/hour and batch Scribe v2 at $0.22/hour](https://elevenlabs.io/pricing/api). Its [realtime API](https://elevenlabs.io/docs/api-reference/speech-to-text/v-1-speech-to-text-realtime) documents `scribe_v2_realtime`, `pcm_16000`, streamed `input_audio_chunk`, manual commit, and stable `committed_transcript`. The batch rate and an existing Creator subscription do **not** establish that this realtime API is included in this account's allowance. Before activation, the owner must verify the actual account's realtime debit route and disabled overage/no-top-up behavior.
