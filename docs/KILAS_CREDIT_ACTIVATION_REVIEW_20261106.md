- Customer receipt settlement is distinct from provider request accounting. A valid unreadable result remains a completed supplier request but releases customer credit. Refusal, invalid/oversized output and known rejection release customer holds; ambiguous transport stays reserved until evidence-based review. No automatic paid retry is added. This customer-facing success condition is explicit in all four consent languages and remains an unapproved production term.
- Receipt credit requests now reject inputs outside a single image of at most 2048 px per side / 5 MiB, 64 category names of at most 160 characters each, and a 12,000 UTF-8-byte aggregate text/schema/framing envelope. Nothing is silently cropped, resized or truncated by this hook. Existing active paid plans retain their original receipt input profile and CHAT accounting with no new wallet admission; a dedicated regression verifies this preservation. Other Finance flows and disabled-activation behavior are unchanged.
- The receipt profile's 32k input value is a FORECAST, not an API-enforced input-token maximum. Exact GPT-6 Luna vision accounting was not established by the current official model sizing table; it lists other named models and detail-dependent behavior. An explicit matching input_accounting_verified contract marker is required in the tariff configuration, is NOT installed, and MUST NOT be set merely to pass configuration validation. The 5-credit / 32k economics are not certified. - Quote retries are additionally bound to the original authenticated account and operation through a server-checked consent header. Account switching, operation changes, expiration or activation rollback cannot redirect an approved request into another account/legacy purchase path.
- Existing unlinked legacy Audio jobs retain duplicate retrieval across activation; no new admission or trial is created for the accepted old key. A SQLite/PostgreSQL regression verifies this.
- VO request fingerprints bind the resolved provider model. A voice/profile change from v2 to v4 requires a new approval; dispatch uses the admitted personal-voice mode instead of silently rereading a changed mode.
