# Inactive credit wallet implementation checkpoint

Base: 5968534f8b8d03b6095ac5ed2262caf5038482d7. New standalone modules are deliberately not imported by routes/startup; no production DDL or balance migration has run.

## Implemented locally

`credit_wallet.py` and explicit candidate schema provide integer milli-credit balances, immutable event records, atomic reservation/capture/release, serial account locks (SQLite immediate transactions / PostgreSQL user-row locks), idempotent fixed-pack orders, validated bounded proof upload and server-role manual review. Upload alone creates no credit. Verified review grants the one-time 99,000 IDR / 2,000-credit pack exactly once, with no expiry. Existing cost credits, subscriptions and Audio seconds are untouched. Unknown interrupted operations retain holds for reconciliation; no automatic timeout refund permits duplicate paid work. Actual debit cannot exceed its accepted reservation.

Eight isolated SQLite tests pass: proof-versus-verification separation, retry conflict/duplicate settlement/release, concurrent overspend (24 attempts against ten available reservations), concurrent review credit-once, cross-account denial, no expiry/read mutation, rejection/resubmission and ledger reconciliation. Python compilation and diff whitespace checks pass. Native PostgreSQL, route integration, migration/backfill, UI, supplier calls and release checks are NOT yet run. This is a foundation, not a completed production credit system.


## Safe integration milestone (activation remains disabled)

The branch now has authenticated manual-purchase, own-account proof upload/download, narrowly authorized admin proof/review routes and localized wallet/invoice/admin templates. New routes are 404 unless KILAS_CREDIT_ENFORCEMENT_ENABLED=yes. No production environment has been changed. The original preview still renders when disabled. This activation flag MUST remain off until every remaining feature adapter and tariff/consent decision is complete; the branch is NOT release-ready.

Verification now requires a human-confirmed unique bank transaction reference. A database unique index fences simultaneous attempts across different customer accounts; losing transactions roll back both grant and review. Review audit records retain the exact proof digest/reviewer/reference. Duplicate proof bytes are a reviewer signal, not independent evidence that money was or was not transferred. Proof is never exposed through static/public blob URLs; own-account and authorized-reviewer downloads use no-store, attachment, nosniff and sandbox headers.

The policy foundation pins the verified owner ID plus canonical email and role; CLIENT_OWNER alone never grants exemption. Synthetic configured rates have no production defaults. Admission binds a SHA-256 digest of immutable server-built inputs, reserves selected free quotas and/or the accepted spending ceiling, and refuses redispatch for every existing terminal/pending admission. Successful historical image usage consumes the lifetime trial without retroactive charging or a data-conversion backfill. Reapplying schema cannot replenish it. Legacy purchased balances and active entitlements are retained.

Chat and generation-image adapters now connect to the policy/ledger at the existing provider reservation/settlement boundary. Owner bypass, provider cost logging, existing paid-plan behavior and supplier safety guards stay distinct. Missing/unapproved payload bounds and unsupported feature adapters fail closed when activation is enabled. The source is deliberately NOT ready for activation: VO characters versus free-duration allocation, partial free-duration quotes, Translator source/output streaming metering and funding integration, receipt pricing/adapter, paid spending-consent UI, legacy purchase migration presentation and interrupted-operation reviewer reconciliation remain incomplete. No claim of complete multi-feature enforcement is made.

Explicit schema release is checksum-idempotent and additive, with PostgreSQL advisory locking. It is not imported by app startup. The separate script requires a reviewed release marker. Rehearsal retains legacy credit rows exactly; operational rollback turns admission off while leaving records intact and allowing settlement of previously admitted jobs. No destructive rollback or invented legacy-credit conversion is provided.

## Pricing reconciliation / decisions

Read-only production checks confirmed canonical owner identity separately; no role was changed or exemption activated. Historical successful output metadata confirms two 2048x2048 PNGs on OpenAI gpt-image-2.5-sunburst, each with 3,568 output tokens and 20/29 input tokens. Recorded application estimated costs are USD0.107140 / USD0.107185, exactly matching 3,568 x USD30/M plus text input x USD5/M. These are estimated records, not provider invoices. Retained usage records do not prove each request's quality option or its input modality breakdown; both operation types are generation, but an absence of reference costs cannot be proved from these summary columns.

The earlier USD1.57504 estimate is the repository's pessimistic forecast (32,768 output + 16,000 text + 64,000 image-input tokens), not a measurement of those two outputs. Do not use it as an actual per-image charge or claim the historical sample guarantees a cost ceiling.

Official OpenAI image-generation guidance states Sunburst/Flare USD30/M image output, USD8/M image input, USD5/M text input, and says model/quality token counts differ. Pricing page also exposes batch/discount rows, which must not be confused with direct realtime Images pricing. Reference editing has additional input image costs. Source: https://developers.openai.com/api/docs/guides/image-generation#cost-and-latency and https://developers.openai.com/api/docs/pricing

Of actual successful 2K samples examined, Sunburst is the only observed model; it is the evidenced default recommendation, not a proven cheapest model across all providers. Recommend seeking approval for 125 credits per bounded Sunburst 2K generation without references, explicit quality, one output and a prompt/input cap. Do not revive Medium/40. Other quality/model/size/reference requests need an approved separate quote; preserve existing features until that policy is approved rather than silently repricing them. Exact quality/cost ceiling still needs reconciliation against an official calculator and retained request evidence; no paid probes authorized.
