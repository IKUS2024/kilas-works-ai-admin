## Verified gaps and changes

- Existing Render inventory has no dedicated execution boundary. The Hub is a 0.5 CPU / 512 MB Python web service. Connected workspace/media execution tools are not an authorized per-Kilas-tenant production runtime. Generated code is never launched on this host. Removed the old local bwrap/subprocess test implementation so remote enablement cannot accidentally activate it.
- `workspace_execution` uses pinned E2B SDK 2.56.0. Each operation creates a fresh ephemeral microVM, no mounts, no inherited production environment or identity tokens, outbound traffic denied, public ingress blocked, kill after 60 seconds and no auto-resume. Before uploading sources it verifies reported CPU, RAM, network and lifecycle policy. No reconnect, pause, timeout extension, dependency installation, generated shell command or automatic replacement VM exists.
- The trusted guest runner is uploaded as a root-owned script inside the VM. Only its child executes user Python, under UID/GID 65534 with empty supplementary groups, `no_new_privs`, empty environment apart from fixed PATH/HOME/TMPDIR/LANG, 10 CPU seconds/process, 256 MiB address space/process, 16 processes, 32 descriptors, 64 KiB file size and zero core dumps. Wall time is 20 seconds. These controls supplement the provider microVM; they are not represented as a host subprocess sandbox.
- Provider hard boundary: up to 2 vCPU / 4 GiB accepted by the adapter, 10 GiB root/workspace filesystem checked in the guest, 60 seconds VM lifetime. Workspace 64 MiB / 4096 entries is a monitored early-stop policy, not an atomic filesystem quota. The provider disk limit is the actual upper bound. CPU limits are per process; total VM compute is bounded by vCPU count and lifetime.
- Before output collection, the trusted runner stops the entire dedicated UID process set until stable, then kills it. Output collection rejects symlinks, hardlinks, devices and foreign-owned files. At most 8 flat UTF-8 source/data outputs, 64 KiB each / 256 KiB total. Server download is streamed with a 512 KiB report cap and 5-second total transfer deadline, closed on rejection. CSV formula payloads are rejected. Binary runtime outputs and extra dependencies are not supported in this first adapter.
- Durable additive table `kilas_workspace_executions` reserves cost **before** dispatch, records opaque VM ID/state, source step key and cleanup status. Unknown create outcomes never redispatch. Unknown/active cleanup blocks concurrency until TTL expires. Cancellation/revision/lease checks fence publication; finally attempts kill, with the explicit provider TTL if kill is uncertain. Cleanup uncertainty is retained, never claimed verified. Budget records survive job/account deletion with nullable references; chat archive still retains artifacts under the existing documented policy.
- Standalone explicit Python requests consume owned uploaded `.py`/safe ZIP or owned same-conversation project artifacts. Project authoring can run Python only when explicitly requested and configured. It retains original sources even if execution cannot be verified; real logs and output ZIPs use existing authorized artifact/download paths. Existing CODE tests also use only the remote adapter. Standard-library Python entrypoint or unittest discovery only; exit status is reported without inventing test coverage/pass counts.
- Progress comes from real dispatch/collection actions. Added localized sandbox/Python/result statuses for Indonesian, English, Spanish and Chinese. No model/layout/selector substitution.
