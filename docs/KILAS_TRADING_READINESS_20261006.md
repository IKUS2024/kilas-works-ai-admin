No `order_send`, broker edits, trade-enabling controls or broker execution code. [MT5 settings](https://www.metatrader5.com/en/terminal/help/startworking/settings) document external Python trading is disabled by default; keep it disabled. Use broker-provided investor/read-only access where supported; confirm support, never infer it from the UI checkbox alone.
2. Minimum first proof may upload one small bounded snapshot through the existing pilot browser session (no new bridge credential). For owner-friendly direct refresh from the app, a narrow short-lived connector credential/secure host transport must be designed and explicitly authorized/configured separately; no public inbound RDP or arbitrary URL-fetch feature. Secure provider/host secret storage; never secrets in chat, repository, logs or model prompt. No always-on collector in this stage.
3. Validate bid/ask, candle times/sequence, UTC, symbol suffix, market session, finite positive values, OHLC consistency and actual contract/tick units. Store provider time, capture/receipt time and last successful sync. Missing/stale/disconnected/out-of-order/mismatched data returns WAIT/UNAVAILABLE without calling AI or opening positions. Use separate last-tick freshness and closed-bar alignment: an old replay or historical closed candle is never declared a current broker quote.
4. Explicit Analyze action: bounded recent closed bars and computed indicators, selected strategy constraints and paper-position state only; one pinned already-configured model (proposed Sol medium), no tools/browsing/planning loops or automatic repair/retry. Proposed initial engineering caps: at most 10 explicit analyses/day, 5000 input/700 output tokens, one in flight, dedup/cached result per source/account binding + bar/snapshot + strategy/model version, plus owner-chosen USD daily/monthly reserve ceilings. These are proposals, not activation or current price estimates. Account login/name/balance/equity/margin/broker positions are excluded from prompts absent a separate data-sharing approval.
5. Structured decision BUY/SELL/WAIT, reasons/evidence, invalidation and proposed SL/TP; position recommendation HOLD/CLOSE/PROTECT references paper position IDs only. Insufficient evidence may WAIT. Validate finite fields/schema, matching snapshot IDs and instrument. Server checks freshness/cost/dedup again after response and deterministic engine sizes/rejects any simulated entry or protective change. Model failure/invalid output never produces a trade. Human review first; later automatic paper application needs explicit scope. Journal input hash, source/time, model/version, usage/cost, proposal, deterministic acceptance/rejection and paper outcome. Genuine model reasoning does not establish predictive accuracy/profitability.
6. Introduce a new broker-data paper workspace/source identity, preserving existing synthetic paper balances/positions/events; never relabel open replay trades or put broker positions in the paper/Finance ledger. Broker quotes feed simulated fills only after tested source-aware settlement. Label real demo quotes versus simulated order fills/costs independently.
